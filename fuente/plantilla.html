    Qué es un token
    
  
    Un token es un nombre que apunta a un valor. El código usa el nombre y nunca el valor. Así, cuando cambia la marca, cambia todo lo que dependía de ella.
    
  
    css
    /* ✗ valor suelto */  .btn { background: #2A39D0; }
/* ✓ token        */  .btn { background: var(--button-primary-bg); }
    

  
    Tres capas, una sola se usa en componentes
    
  
    
    
    Primitivo
    Color crudo, escalas de 12 pasos. Es materia prima.
    --indigo-9: #2A39D0
    
    
    Semántico se usa en componentes
    Dice para qué sirve, no cómo se ve.
    --button-primary-bg: var(--accent-9)
    
    
    Componente
    El CSS que escribís vos.
    background: var(--button-primary-bg)
    
  
    

  
    Cómo se nombran
    
  
    De Figma al CSS: las / pasan a - y se antepone --. La estructura es --<grupo>-<rol>[-<variante>]. Se nombra por rol, nunca por color: no existe un --azul.
    
  
    arrow_forward
    
  
    Grupos: text, bg, stroke, button, feedback, brand, accent, decor y overlay. Las escalas primitivas siguen la convención Radix de 12 pasos: pasos 1–2 fondos, 3–5 componentes, 6–8 bordes, 9–10 sólidos y 11–12 texto.
    

  
    Reglas
    
  
    Valen para personas y para agentes de IA.
    
  
      
    
    1. Nunca escribas un color literal (#hex, rgb(), hsl(), nombres) en CSS de componentes. Usá un token semántico.
      2. 
    
    2. Nunca uses primitivos (--gray-*, --indigo-*…) dentro de componentes. Solo semánticos.
      3. 
    
    3. Elegí el token por lo que significa, no por cómo se ve. Texto de apoyo = --text-secondary aunque hoy sea parecido a otro gris.
      4. 
    
    4. Si falta un token, no inventes un color. Dejá /* TODO: token faltante: … */ y avisá. Un color nuevo debe ser un paso de una escala existente.
      5. 
    
    5. Usá var(--token), nunca copies el valor resuelto.
      6. 
    
    6. Color principal, color del texto de los botones, fuente y radio de botones son lo único configurable. Todo lo demás es fijo: no lo expongas como opción.
      7. 
    
    7. No uses --accent-* directo en componentes salvo los casos del catálogo. Preferí --brand-*, --button-*, --stroke-primary, --text-brand.
      8. 
    
    8. Los estados nunca cambian con la marca (error, éxito, advertencia, info): usá --feedback-*.
      9. 
    
    9. Links: --text-link + subrayado. Texto sobre fondo oscuro: --text-inverse. Texto sobre el botón primario: --button-primary-text.
      10. 
    
    10. Antes de entregar, buscá en el diff #[0-9a-fA-F]{3,8}, rgb(, --gray-, --indigo-. Tiene que dar 0 resultados en archivos de componentes.
      11. 
  
    

    



    
  
    Contrato de configuración
    
  
    Es el objeto que el integrador le entrega al SDK. Se valida antes de aplicarlo: si un dato no cumple, se usa su valor por defecto y el SDK no falla.
    
  
    config.json
    {
  "primary":      "#6D28D9",   // color principal (HEX #RRGGBB o #RGB)
  "primaryText":  "#FFFFFF",   // color del texto de los botones (HEX); por defecto blanco
  "font":         "Poppins",   // Inter, Open Sans, Roboto, Montserrat, Poppins, Lato, Nunito Sans o system
  "radius":       "m",         // xs, s, m, full o custom
  "radiusCustom": 12           // solo si radius = "custom": cualquier número ≥ 0 (px)
}
    
  
    
    
    PropiedadValoresPor defectoQué cambia
    
    
      
    primaryHEX #RRGGBB o #RGB (se normaliza a mayúsculas). Solo se valida que sea un HEX válido.#2A39D0--accent-9 y, derivada de él, toda la escala --accent-1…12
    
      
    primaryTextHEX #RRGGBB o #RGB. Se recomienda contraste ≥ 4.5:1 contra primary; el panel avisa, nunca bloquea (ver Accesibilidad).#FFFFFF--button-primary-text (en Figma, button/primary-text)
    
      
    fontInter, Open Sans, Roboto, Montserrat, Poppins, Lato, Nunito Sans, systemInter--font-family-default
    
      
    radiusxs 4, s 8, m 16, full 999, customfull--radius-button
    
      
    radiusCustomCualquier número ≥ 0 (px), solo con radius: "custom"—--radius-button
    
    
    
  
    Validá también en el servidorCon un HEX inválido se usa el valor por defecto. Con un HEX válido el SDK aplica lo que recibe, aunque el contraste sea bajo: es solo un aviso.
    

  
    Qué cambia y qué no
    
  
    
    
    Cambia con primary
    --accent-1…12, --brand-*, --stroke-primary, --stroke-brand-subtle, --text-brand, --button-primary-bg(-hover), --button-tertiary-*, ilustraciones y Lotties de marca.
    
    
    Cambia con primaryText
    Solo --button-primary-text: el texto de los botones primarios y el tilde de las casillas.
    
    
    No cambia nunca
    Jerarquía de texto, fondos y bordes neutros, estados (--feedback-*), links, botones secundario/peligro/deshabilitado, espaciado, radios (salvo --radius-button), tamaños, estilos de texto, check de éxito y X de error.
    
  
    

    



    
  
    Cómo se aplica
    
  
    Las variables se escriben en el contenedor del SDK, no en el :root de la página del cliente. Los demás tokens ya las consumen: no hay que tocar nada más.
    
  
    En cuatro pasos
    
  
      
    
    1. Cargá los estilos en ordentokens.css, accent-from-primary.css, illustrations.css e icons.css. Siempre en ese orden: gana el último.
      2. 
    
    2. Marcá el contenedor del SDK con sdk-frameAhí se escribe la marca del cliente, no en el :root de su página.
      3. 
    
    3. Aplicá la configuraciónCuatro setProperty sobre el contenedor. Si un HEX no es válido se usa el valor por defecto; el SDK no falla.
      4. 
    
    4. Verificá con tres marcasUna azul, una violeta y una clara con texto oscuro. Usá la lista de verificación.
      5.

    Ilustraciones y Lotties
    
  
    Los SVG se pintan con CSS y los Lotties se reclasifican con un script. Los JSON de Lottie no llevan tokens (el formato no puede leer variables CSS): traen colores hex y el color lo pone el SDK desde afuera. Acá se pintan con la configuración activa del playground.
    
  
    Ilustraciones SVG

Las partes de marca llevan class="ill-primary" (color pleno, --accent-9) o class="ill-primary-50" (variante suave, --accent-8); las fijas usan fill="white" y no llevan clase. No hay un archivo por color.

    Cómo se reclasifica un Lotti
    
  
    Se dibuja con lottie-web en modo SVG. Después, tintLottie() lee el color de cada trazo y relleno: si es azul (B − R ≥ 60) y R > 120 recibe la variante suave (accent-8); si es azul y R ≤ 120, el color pleno (accent-9); lo demás no cambia. Se repite en cada cuadro (enterFrame) porque lottie-web asigna algunos colores recién al animar. No funciona con el renderer de canvas; estos archivos no usan degradados.

    Accesibilidad
    
  
    El panel muestra un único aviso al final de la tarjeta de color: compara el color del texto de los botones contra el color principal. Informa, nunca bloquea el guardado ni rechaza la configuración.
    

  
    Niveles WCAG
    
  
    
    
    ANivel mínimoEl piso de accesibilidad.
    
    
    AADesde 4.5:1El estándar más habitual que exigen leyes y normativas, como la European Accessibility Act y la norma EN 301 549.
    
    
    AAADesde 7:1El nivel máximo y más exigente.
    
  
    

  
    Probá una combinación
    
  
    
    
    
    
    
  
    
  
    3:14.5:17:121:1
    
  
    
  
    El ratio se muestra truncado a 1 decimal. “Leer más” abre la guía de contraste de WCAG en una pestaña nueva.
    

  
    El cálculo
    
  
    javascript
    {{CODE_A11Y}}
    
  
    Canal: c ≤ 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4. L = 0.2126R + 0.7152G + 0.0722B. ratio = (Lmayor+0.05)/(Lmenor+0.05).
    

  
    Medidos con los valores por defecto
    
  
    Valores redondeados. El aviso del panel trunca a 1 decimal, por eso el botón por defecto (8.09) aparece allí como 8.0:1; el nivel no cambia.

      Para trabajar con IA
      
  
      El paquete de assets trae archivos pensados para que un asistente o agente de IA los lea como contexto y escriba código del SDK respetando los tokens y las reglas.
      
  
      
    
      DESIGN.md
      El archivo principal para la IA: qué es un token, las 10 reglas obligatorias, el contrato, el catálogo completo, las recetas de componentes, ilustraciones, íconos, accesibilidad y el checklist final. Se lee completo antes de tocar estilos.
      
    
      tokens.json
      Los mismos tokens en JSON (primitivos, semánticos y medidas), con el valor resuelto y a qué referencia cada uno. Marca qué propiedades son configurables. Sirve para herramientas, validaciones y pipelines.
      
    
      Reglas y checklist
      Las reglas y la lista de verificación de este documento son las mismas que trae DESIGN.md (secciones 2 y 10). Se le pueden pedir a la IA como criterio de revisión antes de entregar.
      
  
      
  
      Cómo usarlos
      
  
        
    
      1. Pasale DESIGN.md como contextoAdjuntalo al prompt o referencialo desde el archivo de instrucciones del proyecto (por ejemplo CLAUDE.md o el equivalente de tu herramienta), para que lo lea al empezar.
        2. 
    
      2. Usá tokens.json para validarSirve para comprobar que un token existe antes de usarlo o para buscar en el código valores sueltos que debieron ser tokens.
        3. 
    
      3. Pedile que cierre con el checklistQue verifique el checklist y que busque en el diff colores literales y primitivos. Tiene que dar 0 resultados en archivos de componentes.
        4. 
  
      
  
      Si falta un tokenLa IA no inventa colores: deja un /* TODO: token faltante: … */ y avisa. Un color nuevo tiene que ser un paso de una escala existente (regla 4).
